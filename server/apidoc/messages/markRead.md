# 确认专属消息已读

客户端在用户点击“我知道了”后确认一条消息已读。客户端应先立即切换到下一条消息，再在后台异步调用本接口；本接口是同步写入，不是 `202` 异步任务。

- **请求方法**：`POST`
- **请求路径**：`/api/messages/:id/read`
- **需要鉴权**：至少提供有效的 User JWT 或设备消息凭证之一
- **加密模式**：端到端加密

## 请求参数

### Path Parameters

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | `string` | 是 | 消息 UUID。 |

### Headers

| Header | 必填 | 说明 |
| :--- | :--- | :--- |
| `Authorization: Bearer <UserToken>` | 否 | 账号专属消息的身份，也可和设备凭证合并使用。 |
| `x-pm-device-token: <messageToken>` | 否 | 当前 Android 或桌面设备的设备消息凭证。 |

至少提供一项有效身份。请求 Body 为空对象即可。

## 返回数据

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": "806ce22e-87bd-4af0-8395-983ad24a1b8c",
    "readAt": 1756780920000
  },
  "success": true
}
```

`readAt` 为服务端首次确认时写入的毫秒时间戳。已经读取的消息再次确认仍返回首次写入的值，不会覆盖已读设备和已读平台信息。

## 权限与幂等规则

- 账号身份可确认目标为该账号的消息；设备凭证仅可确认目标为该设备、且设备类型匹配的消息。
- 两种身份同时存在时，任一身份拥有该消息即可确认；账户消息的 `readPlatform/readDeviceId` 会在持有设备凭证时记录当前设备，否则为空。
- 不属于当前账号或设备的消息与不存在的消息均返回 `404`，避免泄漏消息归属。
- 用户点击“我知道了”后的后台回执失败不会阻塞下一条展示、不会弹加载或错误提示；未成功确认的消息下次启动仍会出现。

## 错误响应

| HTTP 状态 | 说明 |
| :--- | :--- |
| `400` | 消息 ID 为空或参数校验失败。 |
| `401` | 未提供有效 User JWT 和设备消息凭证。 |
| `404` | 消息不存在，或当前身份无权确认该消息。 |
| `500` | 服务端确认失败。 |
