## 一、目标及确定的行为

1. 普通音频下载成功不依赖标签写入成功。标签或歌词处理失败时，音频任务仍为 COMPLETED，并记录警告及可重试结果。
2. 内嵌使用标准逐行 LRC 文本：优先源站原生 LRC，不存在时从有效 KRC/YRC 行起点及文字转换。
3. 原始逐字 KRC/YRC 进入 App 本地逐字索引（以最终音频路径对应的 LOCAL 身份为键）；独立 .krc/.yrc/.lrc 文件仍由原有用户设置决定，不强行生成。
4. 本地播放优先读取有效逐字索引，兜底顺序为旁边逐字文件、音频内嵌标准歌词、旁边逐行歌词、普通索引/历史缓存、在线关键字搜索；普通 LRC 不能覆盖已保存的有效逐字索引。
5. 下载管理顶部改为一行：左返回 / 中「下载中」「已完成」 / 右三点；三点只有图标+文案「编辑」，复用“我的音乐”的 PopupWindow、紧凑菜单行、图标。搜索框、列表、原有筛选、底部操作风格不变。
6. 编辑模式顶部为左关闭 / 中已选数量 / 右完成，不跨 Tab 选中；“下载中”原有全选/反选/删除；“已完成”额外增加“修复信息”。
7. 批量修复只操作已完成的、仍存在且有效的音频，不重新下载；只填充缺失标签，已存在有效的标题/歌手/专辑/封面保持不变。旧版嵌入 KRC/YRC 可以在安全备份原始歌词后转为标准 LRC。
8. 同时最多修复一个文件；同路径上锁；当前播放器加载的本地音频（包括暂停）跳过。中途取消只取消未开始项目，正在提交替换的事务不可中断。
9. 删除仅记录、不删除音频时保留本地歌词索引；实际删除音频且没有其他任务引用时删除其路径索引。
10. 旧下载失败但目标文件有效时，重试先进入元数据修复，而不是重新下载；若音频无效或缺失，继续既有下载重试。
11. 首次打开下载页面不扫描历史音频；旧数据以 UNKNOWN/未检查状态迁移，用户手动触发补写。

## 二、架构拆分与文件级改造

### 1. 歌词解析与双轨存储
- 修改 `download/DownloadLyricResolver.kt`：`ResolvedDownloadLyrics` 扩展 standardEmbeddedText、originalWordAsset、sidecars、source/diagnostic；明确“找不到歌词”和“获取异常”；源站原生 LRC 优先。
- 新增 `download/EmbeddedLyricFormatter.kt`：由 LyricParser 的有效时间轴生成 [mm:ss.xx] 逐行 LRC；排除占位符、空行、异常毫秒及无效结果。保留原始 KRC/YRC 字节文本供 App 内部使用。
- 修改 `lyric/LyricParser.kt`：增强带前置元信息的 KRC/YRC 自动识别；转换仍复用现有解析器；不改变现有播放时间计算语义。
- 修改 `utils/LocalMediaIndexDbStore.kt`：新增独立逐字索引表/字段（推荐 `word_lyric_index`）及操作接口，数据库 v1 -> v2 增量迁移；优先级和旧 `lyric_index` 分离，提供按 LOCAL 文件路径读取、写入及删除；避免普通内嵌 LRC 覆盖逐字信息。
- 修改 `lyric/LyricRepository.kt`：本地优先读有效逐字索引（并可读同名 KRC/YRC），其次正常内嵌/同名 LRC/现有缓存；明确当索引被清理、文件移动时的退化行为。

### 2. 元数据处理与验证
- 修改 `utils/AudioMetadataEmbedder.kt`：分别处理标签字段及封面；只有确需写入时才 commit；按格式能力检查；尽量只写未存在的有效字段；返回细分写入结果，不抛异常导致音频下载失败。
- 新增 `download/AudioMetadataVerifier.kt`：重新打开文件验证音频可读性、要求写入的标题/歌手/专辑、LYRICS 文本可读取可解析、封面可读取；不要求未请求的字段存在；封面仅在支持格式验证。
- 新增 `download/MetadataWriteOutcome.kt`：统一 `UNKNOWN/PENDING/SUCCESS/PARTIAL/FAILED/SKIPPED/INTERRUPTED` 及错误类别和短描述；与主任务下载状态分离。
- 修改 `utils/JavaUtils/JDownloadManager.java` 与 `utils/DownloadManager.kt`：新下载在带真实扩展名的临时音频路径完成标签处理与校验，最后才发布正式文件；避免 jaudiotagger 对 .part 扩展名不兼容。音频完整且标签失败时也发布原始音频，并将警告传递上层；对音频文件有效性失败仍标记下载失败。只在确认持久化成功后记录最终完成。
- 元数据写入与 sidecar 写入互不绑死；sidecar 失败仅形成 PARTIAL/FAILED 警告，不能撤销已下载音频。封面下载失败单独给出原因。
- 对 MP3/FLAC 做重点测试；M4A/OGG 等按库能力尝试，无法安全处理时 SKIPPED，不强行写入。KW 维持当前不嵌元数据行为，必要时按设置保存可用独立歌词。

### 3. 历史文件修复和恢复
- 新增 `download/AudioMetadataRepairer.kt` / `download/AudioFileTransaction.kt`：单并发串行队列、每文件互斥锁、可用空间检查、同目录流式临时副本、写入后验证、持久化事务日志、原文件备份、完成替换及回滚。
- 临时副本采用可识别的音频扩展名（例如 `.repair-{id}.mp3`），不是无扩展名的 .part；预估需要额外一个文件大小的剩余空间及安全余量，空间不足即跳过。
- 替换采用同文件系统移动/原子重命名（若支持）与可恢复的日志状态机；严禁先删除唯一有效副本。崩溃恢复仅检查有记录的未完成事务，不扫描全盘、不自动重新下载。
- 修复时检查 MusicController.currentSong 所指本地文件：包括暂停状态，只要播放器仍持有该路径则 SKIPPED。
- 修复旧 KRC/YRC 内嵌时，先写入 LOCAL 逐字索引并验证，再转为标准 LRC；若索引保存失败，保留原有内嵌逐字信息，不做有损覆盖。
- 修复队列完成后返回成功、跳过、失败数；取消仅停止后续项，不中断文件替换提交阶段。

### 4. 下载任务与数据库
- 修改 `download/task/DownloadTask.kt`：新增元数据状态、短警告文本和必要的处理时间，下载状态继续使用原枚举。
- 修改 `download/task/DownloadTaskDbOpenHelper.kt`：DB_VERSION 1 -> 2，按旧版本 ALTER TABLE 添加非破坏性字段，缺省 UNKNOWN；绝不删除/重建用户数据库。
- 修改 `download/task/DownloadTaskRepository.kt`：序列化/反序列化新字段、原子更新状态、修复结果和路径；兼容旧任务 UNKNOWN；历史 FAILED 且文件有效则交给修复器处理；实际删除音频成功后才清理本地逐字索引。
- 修改 `download/task/DownloadQueueCoordinator.kt`：下载音频结果与元数据结果解耦；每个下载目标路径与修复路径统一互斥；已完成任务共享文件时补全引用状态而不重复改写。
- 清理记录但保留音频、音频已不存在、路径共享和删除失败各情况须分别处理。

## 四、验收用例

- 有原生 LRC + YRC/KRC：内嵌为原生 LRC，LOCAL 逐字索引保留 YRC/KRC，独立 sidecar 遵守设置。
- 仅逐字歌词：正确转换 LRC，原始逐字数据不丢失；只有标准 LRC 时不伪造逐字结果。
- 前置歌曲元信息的 KRC/YRC、空歌词、损坏时间轴、云盘 TXT、无法获取歌词：行为可预测，不阻塞正常音频下载。
- MP3/FLAC 标签读写回环；其他格式支持/跳过分支。
- 音频成功但歌词/封面/标签提交失败：任务 COMPLETED + 警告，后续可修复。
- 旧 FAILED 任务但磁盘有效：不重下载；旧下载任务和用户音频原样存在。
- 批量修复：跳过正在播放/暂停歌曲、空间不足、大文件；模拟取消、强制退出与恢复；无论失败在哪一步都不丢失最后一份有效音频。
- 文件删除、仅删除任务、共享路径、清理歌词索引：无误删、无数据悬挂。
- 管理页：普通模式单行顶部、三点编辑、编辑模式顶部、两 Tab 切换、搜索、批量操作、深浅主题均正确；其余原有功能不回归。
- 整体完成后检查无关工作区文件仍保留，Git 提交仅含本次实际修改。
