# 本地歌单创建简化与自动封面实施计划（2026-11-02）

## 目标与范围
- 统一“我的”与“歌曲更多 → 添加到 → 新建本地歌单”的创建弹窗，参照 `dialog_account_profile_edit_username.xml`，仅保留名称、取消和确认；名称非空、至多 50 字符。
- 创建歌单默认描述为空；无可用封面时在本机显示 `R.drawable.home_feature_cloud_music`，不把 Android 资源路径存进同步字段。
- 从 `pm/icons/new_playlist_新建歌单_压缩.webp` 复制入口图标为 `app/src/main/res/drawable/ic_new_local_playlist.webp`，保留原图。
- 仅本机主动新增歌曲更新封面；删除、排序、同步下行不更新；在线歌单转本地保持原歌单封面和描述。

## 已确认的业务规则（grilling Q1–Q14）
1. 每次确实新增歌曲才更新封面，允许覆盖用户手动选定的封面。
2. 批量以**最后一首实际新增**为准；重复项和无效 ID 不计入。最后一首没有有效封面，或为 `SongType.LOCAL`，本批不更新（不向前回退）。
3. 本地音乐不读取内嵌封面、不生成图片文件。歌曲封面只接受合法的 HTTP(S) 地址；复用 `requestablePlaylistCoverCandidates` 解析 KG `{size}` 和 WY 尺寸。
4. 创建弹窗携带歌曲时，在同一事务中创建歌单、初始曲目和确定的封面；不经过先创建后修改的临时状态。
5. 不上传/下载图片验证 URL；封面显示加载失败时由 UI 走资源回退。
6. 移除歌曲即使删至空列表，仍保留此前封面。同步流只应用已有元信息，不重算歌曲封面。
7. 自动覆盖以前的自定义图片仅清理 App 私有 `files/playlist_covers` 中确定无其他歌单引用的文件，数据库失败、外部图片不清理。
8. 历史歌单明确存储的模板/远程图片/本地图片保持不变；缺失的封面采用新默认图。编辑页的封面选择功能保持独立可用。

## 代码分工
- `ui/dialog/LocalPlaylistCreateDialog.kt` 与 `res/layout/dialog_create_local_playlist.xml`：仅输入名称的 M3 弹窗；继续使用 `PmSlotDialog` 和 `PmMessage`。避免重复提交、销毁后访问 View、失败可重试。
- `utils/playlistUtil/LocalPlaylistAutoCoverRules.kt`：纯规则判断，选择最后成功新增歌曲的可请求封面，不遍历回退。
- `utils/playlistUtil/PlaylistCollectionManager.kt`：在 `addSongsToLocalPlaylistWithResult` 去重、校验后计算封面并维护 StateFlow；创建弹窗传入初始封面，不影响 `OnlinePlaylistToLocalViewModel`。
- `utils/playlistUtil/LocalPlaylistDbStore.kt`：在 `addSongsWithOutbox` 原有事务内更新 `local_playlists.cover`、`payload_json`，和歌曲、outbox 一致提交；失败则没有部分更新。无需 schema migration。
- `ui/mine/MinePlaylistCoverResolver.kt`：更新默认资源并安全清理旧私有封面，保留历史模板解析能力。
- `ui/dialog/AddToPlaylistBottomSheet.kt`：新建入口图标更新；不调整队列、现有歌单目标流程。
- 更新 `pm/AGENTS.md` 与 `pm/components.md`，记录新行为及可复用组件索引。

## 验证与验收
- `gradlew.bat assembleDebug`、`gradlew.bat testDebugUnitTest`。
- 单元规则：空列表、最后一首本地、无效 URL、KG 占位符、批量成功新增末首及重复项。
- 手工回归：空歌单默认封面；创建并携带单曲/多曲；批量末首为本地或无封面；新增同一首不改变封面；删除至空不变；手工编辑封面后新增；在线歌单转本地保留原封面；帐号同步及旧封面保持兼容。
- Git 提交按 UI/图标、数据逻辑/测试、文档分步进行；不纳入任何其他工作区改动。
