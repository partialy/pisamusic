- 右上角更多菜单固定“编辑 / 清除全部”；“清除全部”按**整个终态集合**抓取快照，不受当前搜索词影响；范围包括完成、失败、取消。
- “清除全部”与单条/批量删除同款确认弹窗，默认只清任务记录，可选“同时删除本地文件”；弹窗展示记录条数与可统计文件总大小，确认后只清除快照中的 IDs，新近完成的任务不跟随被删。

### 2.4 详情、复制、删除
- 详情用 `PmSlotDialog`：固定封面+歌名/歌手，内容区含音源、音质、主状态、元数据状态/异常说明、专辑、时长、文件大小、完整路径、创建时间、完成时间（失败/取消为最后更新时间）。
- 歌名、歌手、专辑、完整路径**整行点击复制值**，无复制图标按钮；成功按 Android 版本复用系统剪贴板反馈/PmMessage。时长和大小优先读可访问音频文件，读取失败回退已有任务值；缺失值显示“未知”，不猜测；日期用本地时间精确到秒。
- 删除仅任务记录：绝不删除音频、歌词及本地歌词索引；删除记录+文件：先判断文件正被播放器使用、是否有其他任务共享、是否允许访问及是否为本任务合法文件；跳过占用/共享文件，文件删除失败则保留对应任务记录并汇总失败，**不得把失败计入成功删除**。

- 已完成行若外部文件被移动/删除，派生“文件丢失”状态；保留历史路径、记录和异常信息，不自动删记录。

## 3. 下载核心架构与状态机

### 3.1 数据状态
- 主状态新增 `PAUSING`（短暂收尾状态）和 `PAUSED`；保持已存在枚举字符串不变，避免破坏旧数据库。建议 `PAUSING` 为**持久可恢复的状态**：进程意外结束时安全转为 PAUSED，避免 UI“已暂停”而底层还在写入。
- 任务归类：`QUEUED/PREPARING/DOWNLOADING/PAUSING/PAUSED/PROCESSING` 为“下载中”；`COMPLETED/FAILED/CANCELLED` 为“已完成”。`isActive` 不再同时承担“占槽/可取消/重启恢复/重复检测”四种含义，拆成明确谓词：`isTerminal`、`canPause`、`canResume`、`ownsWorker`、`hasUnfinishedIntent`，防止把 PAUSED 误判为终态。
- 允许转换：`QUEUED → PAUSED`；`PREPARING/DOWNLOADING → PAUSING → PAUSED`；`PAUSED → QUEUED`（同一 taskId、递增执行代次）；`DOWNLOADING → PROCESSING → COMPLETED`；`QUEUED/PREPARING/DOWNLOADING → FAILED/CANCELLED`；`FAILED/CANCELLED → QUEUED`（用户显式重新下载）；`PROCESSING` 只允许其不可中断提交结果 `COMPLETED/FAILED`。禁止过期执行代次修改新状态。
- 下载请求以 `taskId + attemptGeneration` 标识执行代次；请求、数据库状态、回调/内核事件需要核对代次和最新用户意图。暂停和取消不能依赖单个 `Job.cancel` 的异常类型来区分。
- `PAUSING` 时只接受真正可执行的取消意图（如果文件仍处安全传输阶段）；一旦 `PROCESSING` 开始则不接受取消。完成后原子发布终态，UI 使用 StateFlow 观察；完成/取消/失败不可被迟来的 progress 回调“复活”。
- 下载中列表按 `createdAt` 稳定排序、同时间按 id 排序；`updatedAt`/进度更新不改变行顺序。已完成列表按完成/最后更新时间倒序，已有终态只在确实发生业务变化时更新展示，不因渲染变动调整顺序。

### 3.2 队列协调器与运行时
- 保留两个 FIFO worker 与进程内队列，不新增前台 Service。屏幕关闭/离开页面，只要 App 进程存活继续下载；进程被杀后不承诺持续后台运行。
- `Request` 携带执行代次，`claim` 在同一同步边界确认最新状态为 QUEUED、未删除、执行代次一致；旧 Channel 元素即使随后出队也只能丢弃，禁止抢占恢复后的新任务。
- 用户暂停 QUEUED 的任务不占 Worker；下载中/准备中的任务请求停止内核、关闭 OkHttp Call、等待文件写入完全退出，记录实际临时文件大小后发布 PAUSED。释放槽位后，下一个 FIFO 任务运行。
- 全部暂停 / 全部继续先取当前 ID 快照逐项处理；全部暂停仅作用于 QUEUED/PREPARING/DOWNLOADING 的可暂停项，不包含处理中；全部继续只处理 PAUSED，恢复时追加 FIFO，不抢队首，也不会打断其他任务。
- 重启恢复：历史 `PAUSED` 原样保留；因系统/进程终止处于 QUEUED/PREPARING/DOWNLOADING/PAUSING 的新版本任务转 PAUSED，保留 .part 及续传元数据；`PROCESSING` 由现有 `AudioFileTransaction.recoverPending` 先恢复文件提交、核对正式文件完整性，再归类 COMPLETED 或 FAILED（无法证明完整时不误标成功）；旧版本遗留 FAILED 记录按原语义保留，不自动追溯修改历史。
- 恢复/重新下载不创建新行，沿用 taskId；把任务 status 原子置 QUEUED 后发送新代次 Request。重复点击使用同一锁/幂等结果，不重复发入 Channel；恢复失败的账号/权限/路径异常保持 PAUSED 并给出原因。
- 同一 `source + songId + effectiveQuality` 若已有活动或 PAUSED 任务，新增请求提示“已在下载列表中”，不重复创建也不自动继续。实际完成且存在有效文件仍按现有规则跳过；恢复不改变已解析的实际音质。
- 原有 `identityLocks` 与 `pathLock` 保留，同文件下载/修复/删除应共享互斥协议；临时文件、正式文件和 sidecar 不允许并发交叉写入、修复或删除。

### 3.3 SQLite 增量迁移
- `DownloadTaskDbOpenHelper` 从 v2 升至 v3，严格增量 ALTER，保留已有 `download_tasks` 行、已有状态字符串、文件路径、元数据、错误及歌词副文件。
- 建议新增：`attempt_generation INTEGER NOT NULL DEFAULT 0`、`resume_etag TEXT`、`resume_last_modified TEXT`、`resume_total_bytes INTEGER`、`resume_quality_key TEXT`、`resume_resource_identity TEXT`（用于安全校验的摘要/稳定标识，绝不存带凭证临时 URL）、`pause_reason TEXT`；可按实际实现最小化，但验证元数据和执行代次必须有持久承载。
- 保留 `downloaded_bytes`/`total_bytes` 作为 UI 派生进度；权威续传偏移以**实际 .part 字节长度且与已保存响应元数据一致**为准，任何不一致都不得盲目追加。
- 迁移逻辑对旧行所有新字段使用安全默认值，无强制扫描下载目录；新版本只有在执行恢复/续传时读取对应 .part。原有未知元数据状态 UNKNOWN 不变。
- 数据写入保证同一任务状态、代次、续传校验信息同步提交，避免异步 `persist()` 的旧快照晚于新快照落库；推荐在单线程数据库调度器里使用有版本约束的有序更新/事务，或以单任务单调代次 `WHERE id=? AND attempt_generation=?` 约束。
- 下载前设置、更新、删除状态需处理用户已移除任务 ID；快照删除后任何延迟回调均不得重新 INSERT 对应行。为现有 `removedIds/removingIds` 加代次和删除防护测试。

## 4. HTTP 真正断点续传与本地文件事务

### 4.1 首次下载
1. 通过现有 `DownloadUrlResolver` 取有效 URL；保留现有账户/音质权限检查。确定最终的 `effectiveQuality` 并写入任务，不保存可能带签名的临时 URL。
2. 发起 GET 时明确使用 `Accept-Encoding: identity`，禁止传输内容编码造成字节偏移语义错误。仅在获得可用 `Content-Length` 等可信长度时计算百分比。
3. 响应成功时将强 ETag（弱 ETag 不作为严格 If-Range 校验依据）、Last-Modified、预期总长度、有效音质和资源身份原子保存为续传元数据。下载只写本任务独占 `<target>.part`；下载写入及光标更新以磁盘一致性为准。
4. 读取流遇到“暂停”将 Call 取消/退出，**不清理 .part**；等待输出流关闭、数据落盘，再保存已写字节数并标记 PAUSED。普通网络/HTTP 错误标为 FAILED，保留可安全续传的 .part。主动取消则中断，清理本任务专属的 .part/.stage 临时文件，标记 CANCELLED。

### 4.2 恢复续传
1. 按原任务 `taskId + attemptGeneration` 恢复，校验原存储目录是否可用，检查临时文件为正常文件且路径仍属于该任务。用户修改默认下载目录后**继续使用原任务目录**，旧目录不可用则提示并保持 PAUSED，不擅自搬运。
2. 重新检查系统账号/有效 VIP/现有 `MusicQualityAccessPolicy` 权限，重新取该任务**原实际音质**的下载 URL；失权时保持 PAUSED 和 .part 并告知原因，绝不自动降级。源站不提供原音质时保持可重试状态，不能默默改成较低音质。
3. 存在严格可验证的续传条件时发送 `Range: bytes=<part.length>-`，有强 ETag 时发送 `If-Range`；否则可用有效 Last-Modified。不能确证资源与 .part 一致时，安全地从 0 重新下载（使用独立新临时文件/受控替换，不向旧 .part 盲目追加）。
4. `206`：严格解析 `Content-Range`，起始必须等于请求偏移；结束和总量不矛盾、校验器和保存的资源身份保持一致、`Content-Encoding` 与字节流吻合。合格才以 append 模式续写，计算 `partSize + newBytes`。
5. `200`（Range 被忽略，或 `If-Range` 不匹配）：**禁止 append**；丢弃旧续传资格并按完整新文件处理，始终保留最后一份已验证成功文件不被破坏。
6. `416`：检查 `Content-Range: bytes */total` 与本地长度；只有额外完成音频完整性验证、资源身份检查全部通过时才能当作已满，否则重新下载。不把“已有 N 字节”直接推断为音频成功。
7. URL/重定向失效（例如 401/403/404）时依照现有网络取链逻辑**有限次数重新解析**，不要对无效 URL 无限重试；再次请求仍执行相同 Range 校验规则。临时网络错误留 FAILED + .part 等用户显式重试。
8. 只有文件完整、验证可读、元数据/歌词处理（允许非致命附加信息异常）结束并安全发布正式文件后才更新 COMPLETED；失效/重复回调不能把 CANCELLED/PAUSED 或已删除任务改成完成。

### 4.3 完成、取消、重试与崩溃恢复
- 继续保留既有 `.part → .stage.<extension> → <target>` 文件流水线；`.part` 只归属单个任务，目标路径由任务记录锁定。暂停只允许在音频流传输阶段，进入 PROCESSING 后禁用暂停/取消。
- stage 中的封面/标签/歌词流程复用 `DownloadManager.kt`、`AudioMetadataVerifier.kt`、`LyricSidecarWriter.kt` 和 `AudioFileTransaction`；音频有效、标签失败时仍 COMPLETED + metadata warning，勿退化为 FAILED。
- 失败但已有可读正式音频：遵循 11-06 既有规则优先做信息修复和状态恢复，不重复下载。失败但只有 .part 则尝试断点续传；已取消由于 Q6 删除了 .part，从 0 开始重新下载，沿用原记录身份。
- 处理进程终止时，先执行现有交易日志恢复；确定已发布完整文件则标 COMPLETE；仍有 .part 则 PAUSED；不能核实文件完整性则保持安全非完成状态并展示原因。
- 更新内核 `JDownloadManager` 的动作区分 `pause(id)`、`cancel(id)`，以及“暂停请求导致的 I/O 异常”和真正的失败；`DownloadManager` 回调向协调器返回明确暂停/取消/成功/错误事件。
- 文件写入的临时尺寸/修改时间与存储的响应元数据需对应；用户手动篡改 .part、盘空间不足、权限变化、突然拔出存储介质等情况不造成越界写入、半文件误完成或删除其他文件。
- 不定期清理 PAUSED .part（Q42）；仅主动取消、重新完整下载后替换掉旧进度、删除任务及经确认的清理动作可以释放它，且要控制空间释放结果的准确性。

## 5. 清理和文件安全设计

- 单条删除、编辑批量删除、已完成“清除全部”共用 `DeleteDownloadTasksUseCase`（可以放在 task 包），确认弹窗复用 `PmSlotDialog` 和 `dialog_local_music_delete_confirm.xml`。清除全部在**确认瞬间**采集已完成 Tab 下所有终态 ID 快照，和搜索结果无关。
- 任务/资源按规范化（canonical）真实路径检测：只操作数据库记录的目标及对应合法同目录 .part/.stage/sidecar；校验路径父目录及文件所有权，避免用户路径/恶意同名旁文件被误删。对 symlink、相对路径、越界目录采用拒绝删除处理。
- 删除时串行化与下载工作槽、修复锁、sidecar 写入事务；不允许在有下载内核仍写入时直接删文件。未结束任务必须先协调停止/取消，再等待真正执行完成。
- 若用户选择“同时删除文件”，正在播放/暂停但 Media3 持有文件路径的条目跳过删除且保留记录；同一路径若还有**未参与清除的其它记录**共享，则保留文件，本次记录允许仅清除引用，报告“共享文件保留”。
- 单条文件删除失败：保留该任务记录（含路径和错误说明），其它条目可继续；准确汇总删记录数、删文件数、保留共享数、跳过占用数、失败数。取消不误报成功。
- 多个待删除任务共享同一路径：对本次选择集合先构建引用计数与文件删除计划，同一文件仅物理删除一次，避免重复删或误判成功。清理 sidecar、LOCAL word-lyric 索引也按最终实体文件删除结果进行，成功删除音频且无人引用后才执行。
- 删除记录但保留实际音频时，不删歌词索引；用户之后从“我的 → 已下载”仍能读取原文件。已完成“清除全部”的大小统计只累加可读取的去重实体音频大小，不以历史下载量当成磁盘占用。
- 数据库删除与文件删除非原子：先创建本次删除意图及安全快照、执行文件删除，再仅对成功对象删除记录；异常可重试且幂等，允许剩余失败记录继续可见。不可通过“数据库先删了”掩盖磁盘文件清理失败。

- `DownloadTaskAdapter` 采用 `ListAdapter + DiffUtil` + payload 更新变化区域（进度、速度/状态及选择）并使用稳定 ID，避免 200ms 左右进度更新导致整行重新绑定封面、闪烁或重新排位；页面不可见时不绘制帧。
- 状态 Tag 与音质 Tag 单独 Formatter/Binder：
  - 主状态：已完成、待修复、文件丢失、失败、已取消，按 Q28 单一优先级展示；颜色使用语义化 primary / warning / error / neutral。
  - 音质：`wy-br:128000 → 128`、`wy-br:320000 → 320`、`kg:128 → 128`、`kg:320 → 320`、`kg:high → HIGH`、`wy-level:lossless → LOSSLESS`、`wy-level:hires → HI-RES`；`exhigh` 等按现有音质档位映射，`cloud:default` 显示适合的“默认”文本；不直接展示原始内部 key，不凭 `br:max` 虚构实际音质。

- 深浅色主题：从资源/主题语义色提取淡蓝背景与高光 alpha，保证文字对比度；选中态/点击 ripple 要叠在背景上，不让动画遮挡封面和文本。RecyclerView 复用时重置 shader/动画、进度、Tag、选中样式。
- 图片封面继续使用当前 `DownloadTaskAdapter` 的 `SongCoverUrl.getRemoteCover(..., SIZE_SMALL)` 优化；该文件**现有未提交改动必须保留、整合，不能回退**。

- 抽出 `DownloadTaskActionMenu` 负责按主状态构造 `ActionMenuItem`，调用现有 `ActionMenuBottomSheet.show`（信息头使用已有歌曲封面/标题样式）；菜单动作在 Sheet 完全关闭后执行。

## 9. 测试矩阵与验收标准

### 9.1 网络/文件
- 首次正常 200、可续传 206、服务器忽略 Range 返回 200、416 边界、错误 Content-Range 起点、总长不一致、ETag 改变、Last-Modified 改变、无校验器的保守全量重下。

- 无 Content-Length、断线、超时、磁盘满、文件权限异常、存储目录修改、手工删除/篡改 .part、服务器转码/重定向后资源变化。
- 已暂停重启保持暂停；传输中被杀下次进入暂停；处理中被杀由事务恢复；下载成功但歌词/标签失败仍保留完整音频并显示“待修复”。

### 9.2 竞争条件/状态机
- 连点暂停/继续/取消、暂停瞬间下载完成、全部暂停与新增入队交错、全部继续与单项继续重复、旧 Channel 请求过期、旧回调落后于重试代次。
