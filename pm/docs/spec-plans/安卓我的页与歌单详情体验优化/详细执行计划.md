# Android 我的页与歌单详情体验优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除“我的 → 歌单”大量数据时的切页卡顿，修复歌单详情顶栏与播放横幅的误触/点击穿透，并为所有歌单详情提供同款本地搜索过滤和双击回顶能力。

**Architecture:** “我的”页从 `NestedScrollView + wrap_content ViewPager2 + 禁用嵌套滚动的 RecyclerView` 改为 `CoordinatorLayout/AppBarLayout + 全高 ViewPager2 + 页面级 RecyclerView`，让歌单行真正按视口创建和回收。歌单详情在 `cn.partialy.pm.ui.playlistdetail` 建立共享模块，以一个 Header Adapter、一个 Content Adapter 和一个 Interaction Controller 隐藏四种详情页共同的 Header、搜索、吸顶、触摸消费和双击回顶实现；酷狗、网易、本地歌单和“我的收藏”Activity 只保留数据加载与播放业务。

**Tech Stack:** Kotlin、Android ViewBinding、RecyclerView / ListAdapter / ConcatAdapter、ViewPager2、CoordinatorLayout / AppBarLayout、Material Components、JUnit 4

## Global Constraints

- 只处理当前 `pm/` Android 项目，不修改 `yixi/`。
- 当前工作树已有用户修改；尤其 `PlayerActivity.kt`、`strings.xml` 等文件不得覆盖或回退。新增歌单详情文案放入独立 `strings_playlist_detail.xml`，不触碰现有 `strings.xml`。
- 不进入 `../example/`，不复制 SPlayer 或其他参考项目实现。
- 不新增第三方依赖；使用项目已有 Material、RecyclerView、ViewPager2、Coil 和 JUnit。
- 搜索 UI 复用 `bottom_sheet_playlist.xml` 的 40dp 输入框、右侧“取消”、`playlist_search_hint` 和现有主题颜色，不再创建另一种视觉风格。
- 歌曲过滤字段固定为歌名 `SongInfo.name` 与歌手 `SongInfo.artist`，先 `trim()`，再 `contains(ignoreCase = true)`；不搜索 ID、专辑、音源或播放地址。
- 搜索只影响当前显示行；“播放全部”继续播放完整歌单，点击搜索结果仍按 `type + id` 在完整歌单中定位。
- 原始歌单顺序和原始序号必须保持；过滤后不能把结果重新编号为 1、2、3。
- 网络歌单后台补齐歌曲时，当前搜索结果必须自动重新计算；不能要求用户清空并重新输入关键词。
- 点击顶栏空白、吸顶横幅空白、横幅右侧首数区域不得播放任何歌曲；只有明确的“播放全部”图标/文字操作区执行播放。
- 双击顶栏歌单名称或空白区域立即回到列表第 0 项；返回、收藏、更多按钮仍保持单击行为。
- 不启动、安装或重启 App；自动化构建完成后，由用户做真机/模拟器体验验收。
- 本轮会改变“我的”页面滚动结构和歌单详情模块职责，完成后必须同步更新 `AGENTS.md` 与 `design-html/components.md`。

## 一、已确认根因与产品规则

### 1. “我的 → 歌单”切换卡顿

当前调用链：

```text
MineFragment
  └─ NestedScrollView
      └─ MineViewPagerNestedHost
          └─ ViewPager2(layout_height=wrap_content)
              └─ MinePlaylistsTabFragment
                  └─ RecyclerView(layout_height=wrap_content, nestedScrolling=false)
```

`MineFragment.adjustMineViewPagerHeightForCurrentPage()` 在切页时以 `UNSPECIFIED` 高度重新测量整个 Fragment；“歌单”页 RecyclerView 又是 `wrap_content + nestedScrolling=false`，因此大量歌单会在测量阶段创建/绑定大量行。计划必须删除动态整页测量链路，而不是通过 `setItemViewCacheSize()`、延迟 100ms 或关闭动画掩盖问题。

### 2. 歌单详情点击穿透与误播放

`activity_playlist_detail.xml` 中 `headerBar` 和 `stickyPlayAllBar` 覆盖在 RecyclerView 上方。顶栏空白没有触摸消费者时，事件会落到下方可见歌曲行；同时 Header 和吸顶横幅当前把整条 `playAllRow/stickyPlayAllRow` 都绑定为播放，点击首数或空白也会播放。计划把“触摸屏障”和“播放动作区”分开：整条横幅负责消费，只有左侧显式动作容器负责播放。

### 3. 搜索交互冻结

- Header 的 `n首` 右侧新增搜索图标。
- 吸顶“播放全部”横幅同位置也显示搜索图标。
- 点击顶部 Header 搜索图标：在 Header 横幅下方展开输入框。
- 点击吸顶搜索图标：先立即回到顶部，再展开同一个 Header 输入框并弹出键盘，避免维护两份输入状态。
- 点击取消或搜索展开时按系统返回：清空关键词、收起输入框、隐藏键盘、恢复完整列表；第二次返回才退出页面。
- 无结果时显示“未找到匹配歌曲”，Header 保留可见。

```kotlin
internal data class PlaylistDetailSongRow(
    val song: SongInfo,
    val originalIndex: Int,
)

internal fun filterPlaylistSongRows(
    songs: List<SongInfo>,
    rawQuery: String,
): List<PlaylistDetailSongRow> {
    val query = rawQuery.trim()
    return songs.mapIndexedNotNull { index, song ->
        val matched = query.isEmpty() ||
            song.name.contains(query, ignoreCase = true) ||
            song.artist.contains(query, ignoreCase = true)
        if (matched) PlaylistDetailSongRow(song, index) else null
    }
}
```

- [ ] **Step 3: 实现 Header Adapter 的深模块接口**

Header Adapter 只暴露本文“目标文件结构”中列出的状态更新方法。ViewHolder 内保存当前 `TextWatcher`，绑定前先移除旧 watcher，避免 RecyclerView 重绑后一次输入触发多次过滤。输入中的每个字符由 Controller 调用 `headerAdapter.rememberSearchQuery(query)` 保存但不触发 Header 重绑，同时调用 `contentAdapter.setSearchQuery(query)`；这样列表更新不会让输入框失焦。

```kotlin
private var watcher: TextWatcher? = null

fun bind(state: PlaylistDetailHeaderState, actions: PlaylistDetailHeaderActions, requestFocus: Boolean) {
    watcher?.let(binding.playlistSearchInput::removeTextChangedListener)
    if (binding.playlistSearchInput.text.toString() != state.searchQuery) {
        binding.playlistSearchInput.setText(state.searchQuery)
        binding.playlistSearchInput.setSelection(state.searchQuery.length)
    }
    watcher = binding.playlistSearchInput.doAfterTextChanged {
        actions.onSearchQueryChanged(it?.toString().orEmpty())
    }
    binding.playAllRow.setOnClickListener { }
    binding.playAllActionContainer.setOnClickListener { actions.onPlayAll() }
    binding.searchPlaylistHeaderButton.setOnClickListener { actions.onSearchRequested() }
    binding.playlistSearchCancelText.setOnClickListener { actions.onSearchCancelled() }
}
```
