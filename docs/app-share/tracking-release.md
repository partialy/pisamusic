# App 分享追踪发布与验收记录

本功能实施依据 `tracking-plan.md`，保留旧 `plan.md` 的历史记录。推广统计不包含歌曲、歌单和一起听分享，也不代表安装或注册转化。

## 发布前配置

1. 设置独立的 `APP_SHARE_ATTRIBUTION_SECRET`，使用安全随机生成的至少 32 字节密钥，避免与账号或设备 JWT 密钥复用。
2. API 与官网同站部署，确认反向代理 HTTPS、转发头和 Cookie 生效；身份响应不得由 CDN 缓存。生产 Cookie 必须具备 Secure、HttpOnly、SameSite=Lax。
3. 同步部署官网 `/app-share/index.html` 和页面脚本，确认 `/app-share` 规范到 `/app-share/`，没有回退成 SPA 首页；该入口保持 noindex，不加入 sitemap。
4. 管理后台 App 分享配置改用 `https://pisamusic.partialy.cn/app-share/`。管理员修改文案不改变既有短码。
5. 通过「内容与协议」更新隐私政策并发布。现有保存逻辑在正文实际变化时自动递增版本，勿手动修改数据库版本号。

## 隐私政策增补文案

上线前须将以下内容合并到当前正式隐私政策中，并同步修正原有 Cookie 章节仅用于偏好设置的描述，避免与推广归因用途冲突。不得用本地测试库正文覆盖线上管理员维护的政策。

推广分享与访问统计

使用“分享App”功能时，我们会根据经验证的设备身份及当前账号（未登录时为该设备的游客身份）生成专属随机短码。不同账号或设备分别保存记录，短码本身不包含账号ID、设备ID、设备指纹或认证令牌。服务端保存分享人与设备的必要展示信息及历史快照，用于管理推广链接和统计效果；这些身份信息不通过公开短码接口向访问者展示。

访问推广页面时，我们使用浏览器中的匿名随机访客标识、服务端加盐后的访客摘要、访问时间以及经过限制的浏览器和来源页面信息，统计推广页面访问次数及每日独立访客。我们不会通过这些标识进行跨设备或跨浏览器身份识别。

我们使用有效期为7天的第一方签名Cookie记录最近一次有效推广访问的归因。Cookie不包含分享人的账号、设备身份或认证令牌。下载入口可使用当前链接中的推广码或有效Cookie，将成功发起的Android或Windows安装包下载跳转计入对应推广记录。下载触发次数不代表下载完成、安装、激活、注册或邀请成功。推广码不会附加到第三方安装包下载地址。

推广访问和下载详细事件默认保留180天（实际保留期以服务端运营配置为准），专属链接主记录与每日汇总长期保留，用于历史效果分析。账号注销、设备记录删除或链接失效后，历史统计与必要的展示快照不会随之自动删除。管理人员可使推广码永久失效，失效后不再接受该码的新推广统计。

你可以清除或禁用浏览器Cookie和本地存储、移除链接中的推广参数，或停止使用推广分享功能；已保留的数据处理及相关权利请求可通过App反馈或官方联系方式提出。禁用存储可能使跨页面或后续访问无法继续保留归因，但不会阻止普通安装包下载。

## 验收关注点

- 同账号同设备复用短码，账号、设备和游客身份隔离；失效后生成新码。
- 页面刷新新增PV，事件重试不重复；同访客同日跨码全站UV只计一次。
- A页早开晚返回不覆盖后开的B归因；7天过期、失效码和禁Cookie场景正确。
- 两个平台下载均只在成功跳转时记录一次全站与推广触发；外部地址不附带推广码。
- Android首次失败可重试，离线与账号切换无串码；真机验证二维码、复制和系统分享。
- Admin筛选、详情、失效、CSV和30秒可选刷新保持一致。
- 部署后使用真实HTTPS环境验证Cookie、反代静态路由及隐私政策版本；本地编译不替代这些验收。
